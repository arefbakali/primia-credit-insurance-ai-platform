# Makina Database Schema Documentation

## Database: Supabase (PostgreSQL)

This document describes the complete database schema for the Makina insurance platform based on code analysis.

---

## Table: `users`

**Purpose**: Stores user accounts for authentication and authorization.

### Columns

| Column Name | Data Type | Constraints | Description |
|------------|-----------|-------------|-------------|
| `id` | UUID | PRIMARY KEY, NOT NULL | Auto-generated unique identifier (Supabase default) |
| `email` | VARCHAR/TEXT | UNIQUE, NOT NULL | User email address (used for login) |
| `password` | VARCHAR/TEXT | NOT NULL | User password (stored in plaintext - **SECURITY ISSUE**) |
| `name` | VARCHAR/TEXT | NULLABLE | User's full name |
| `role` | VARCHAR/TEXT | NOT NULL, DEFAULT 'user' | User role: 'user' or 'admin' |
| `created_at` | TIMESTAMP | DEFAULT NOW() | Account creation timestamp (Supabase default) |

### Constraints
- **Unique Constraint**: `email` must be unique (error code: 23505)
- **Default Role**: New users default to 'user' role
- **Password Storage**: ⚠️ **SECURITY WARNING**: Passwords are stored in plaintext. This is a critical security vulnerability and should be replaced with hashed passwords (bcrypt, argon2, etc.)

### Operations
- **INSERT**: Registration creates new user with default role 'user'
- **SELECT**: 
  - Login: Filters by email and password match
  - Get Users: Returns email, name, role, created_at
- **UPDATE**: Role can be updated by admin
- **DELETE**: Not implemented in codebase

### Sample Data (from seedUsers.js)
```javascript
{ email: 'admin@makina.com', password: 'adminpassword', name: 'Admin Makina' }
{ email: 'user@makina.com', password: 'userpassword', name: 'Simple User' }
```

## Table: `quotes`

**Purpose**: Stores insurance quote requests and their processing status.

### Columns

| Column Name | Data Type | Constraints | Description |
|------------|-----------|-------------|-------------|
| `id` | UUID | PRIMARY KEY, NOT NULL | Auto-generated unique identifier (Supabase default) |
| `user_email` | VARCHAR/TEXT | NOT NULL, FOREIGN KEY? | Email of user who requested the quote (references users.email) |
| `description` | TEXT | NULLABLE | Description of the quote request (e.g., "Analyse automatique du rapport financier") |
| `sector` | VARCHAR/TEXT | NULLABLE | Business sector (e.g., "BANQUES", "ASSURANCES", "DISTRIBUTION") |
| `bank_report_path` | VARCHAR/TEXT | NULLABLE | File path to uploaded financial report (stored in backend/uploads/) |
| `status` | VARCHAR/TEXT | NOT NULL, DEFAULT 'pending' | Quote status: 'pending', 'generated', 'confirmed', 'updated' |
| `base_amount` | DECIMAL/NUMERIC | NULLABLE, DEFAULT 0 | Base insurance premium amount (in DT - Tunisian Dinars) |
| `tva_rate` | DECIMAL/NUMERIC | NULLABLE, DEFAULT 19 | TVA (Tax) rate percentage (default: 19%) |
| `total_amount` | DECIMAL/NUMERIC | COMPUTED/GENERATED | Total amount including TVA: `base_amount * (1 + tva_rate / 100)` |
| `admin_notes` | TEXT | NULLABLE | Internal notes added by admin |
| `created_at` | TIMESTAMP | DEFAULT NOW() | Quote request creation timestamp (Supabase default) |
| `updated_at` | TIMESTAMP | NULLABLE | Last update timestamp (manually set on update) |

### Constraints
- **Default Status**: New quotes default to 'pending'
- **Default TVA Rate**: 19% (Tunisian standard)
- **Computed Column**: `total_amount` is likely a database-generated column or computed via trigger

### Status Values
- `pending`: Initial state, waiting for admin review
- `generated`: Quote has been generated by admin
- `confirmed`: Quote has been confirmed/accepted
- `updated`: Quote has been updated after confirmation

### Sector Values (from UserDashboard.tsx)
```
- "BANQUES"
- "ASSURANCES"
- "SERVICES FINANCIERS"
- "DISTRIBUTION"
- "AGROALIMENT BOISSONS"
- "PROD MENAGER SOINS PERSO"
- "INDUSTRIES"
- "BATIMENT MATERIAUX CONSTRUCTION"
- "MATERIAUX DE BASE"
```

### Operations
- **INSERT**: Users create quote requests with sector and optional bank report file
- **SELECT**: 
  - Users see only their own quotes (filtered by user_email)
  - Admins see all quotes
  - Ordered by created_at descending (newest first)
- **UPDATE**: Admins can update base_amount, tva_rate, status, admin_notes
- **DELETE**: Not implemented in codebase

### Relationships
- `user_email` → `users.email` (logical foreign key, not enforced by database)

## Table: `financial_results`

**Purpose**: Stores AI-analyzed financial data extracted from PDF reports using Google Gemini AI.

### Columns

| Column Name | Data Type | Constraints | Description |
|------------|-----------|-------------|-------------|
| `id` | UUID | PRIMARY KEY, NOT NULL | Auto-generated unique identifier (Supabase default) |
| `company_name` | VARCHAR/TEXT | NOT NULL | Company name extracted from financial report |
| `net_result` | DECIMAL/NUMERIC | NULLABLE | Net profit/loss (in DT). Negative values indicate losses |
| `revenue` | DECIMAL/NUMERIC | NULLABLE | Total revenue/Chiffre d'affaires (in DT) |
| `margin` | DECIMAL/NUMERIC | NULLABLE | Profit margin percentage (without % symbol) |
| `status` | VARCHAR/TEXT | NOT NULL | Financial status: 'win' or 'loss' |
| `processed_at` | TIMESTAMP | DEFAULT NOW() | Timestamp when analysis was performed |

### Status Logic
- `win`: Company is profitable or in good financial health
- `loss`: Company has losses or financial difficulties

### Extraction Rules (from analyze_financials.py)
- **Revenue**: Extracted from "Chiffre d'affaires", "Revenus", "Total des revenus", "Total produits d'exploitation"
- **Net Result**: Extracted from "Résultat net", "Perte nette", "Résultat net de l'exercice", or calculated from components
- **Margin**: Only if explicitly stated as percentage
- **Status**: Determined by net_result value or keyword analysis (loss keywords: "Perte", "Déficit", "Résultat déficitaire", etc.)

### Unit Handling
- Values in "DT" (Dinars) are kept as-is
- Values in "KDT" or "MD" (Thousand Dinars) are multiplied by 1,000

### Operations
- **INSERT**: Created by AI analysis script (analyze_financials.py) when processing PDFs
- **SELECT**: Used to export data to CSV (extract_to_csv.py)
- **DELETE**: Can clear all records (requires service role key permissions)

### Usage
- This table is populated by the Python AI service but is **NOT currently integrated** with the main quote workflow
- Data is stored but not linked to quotes table

## Security Considerations

### Critical Issues

1. **Plaintext Passwords** ⚠️
   - Passwords are stored in plaintext in the `users` table
   - **Recommendation**: Implement password hashing (bcrypt, argon2) immediately

2. **No Foreign Key Constraints**
   - `quotes.user_email` should have a foreign key to `users.email`
   - **Recommendation**: Add foreign key constraint for data integrity

3. **File Storage**
   - Bank reports stored in local filesystem (`backend/uploads/`)
   - **Recommendation**: Consider Supabase Storage for better scalability and security

4. **No Row Level Security (RLS)**
   - Code does not show RLS policies
   - **Recommendation**: Implement RLS policies in Supabase for additional security

## Notes

1. **total_amount Calculation**: The `total_amount` field in quotes is displayed in the frontend but never directly inserted/updated in code. It's likely a computed/generated column: `base_amount * (1 + tva_rate / 100)`

2. **AI Integration Gap**: The `financial_results` table exists and is populated by the AI service, but it's not integrated with the quote workflow. Quotes are processed manually by admins.

3. **Missing Tables**: Models exist for `Credit` and `Insurer` but no corresponding tables are used in the codebase. These appear to be planned features.

4. **Database Connection**: All database operations use Supabase client (`@supabase/supabase-js`) with REST API calls, not direct SQL connections.

## Schema Evolution Recommendations

1. Add foreign key constraint: `quotes.user_email → users.email`
2. Add `updated_at` auto-update trigger for quotes table
3. Implement password hashing before production
4. Add indexes for frequently queried columns
5. Consider linking `financial_results` to `quotes` via a foreign key
6. Add audit logging table for tracking quote status changes
7. Consider adding `deleted_at` for soft deletes instead of hard deletes
